
## 一、主题卡的定位（先给评估者一个“为什么需要它”）

### 主题卡是什么？

> **主题卡 = 群聊中围绕同一件事的“信息容器”**

它把**零散的聊天消息**，组织成一个**可管理、可回顾、可追踪的主题单元**。

### 主题卡解决什么问题？

* 群聊中**同一话题被打散在大量消息里**
* 决策卡 / 行动卡很多，但**不知道它们属于哪件事**
* 新成员不知道“这个群最近在忙什么”

👉 **主题卡 = 决策卡 + 行动卡 + 关键消息的上位结构**

---

## 二、主题卡在整体架构中的位置（非常关键）

```
群聊
 ├── 主题卡 A（如：版本 1.2 上线）
 │     ├── 决策卡 × 2
 │     ├── 行动卡 × 5
 │     └── 关键原文锚点
 ├── 主题卡 B（如：家长会安排）
 └── 零散未归类消息
```

**一句话给评估者：**

> 我们通过主题卡，把“聊天流”转化为“可管理的协作单元”。

---

## 三、主题卡信息结构设计（卡片字段）

### 1️⃣ 主题卡基础信息（卡片头部）

| 字段       | 说明                        |
| -------- | ------------------------- |
| **主题标题** | 自动生成 + 可编辑（如：`版本1.2上线讨论`） |
| **状态**   | 进行中 / 已完成 / 已搁置           |
| **创建来源** | 群聊 / 手动创建                 |
| **创建时间** | 自动记录                      |
| **关联群聊** | 群名称                       |

📌 状态用于摘要、筛选、进度感知

---

### 2️⃣ 主题摘要（AI 生成，可编辑）

> 「本主题围绕版本 1.2 上线时间、功能范围及分工展开讨论，目前已确定上线时间为周五，部分功能仍待确认。」

* 默认折叠
* 点击展开
* 编辑后标记「人工修改」

👉 **这是评估者很喜欢的“AI 辅助但可控”设计**

---

### 3️⃣ 主题内容区（三大模块）

#### 📌 A. 决策卡区

* 决策卡列表（时间倒序）
* 显示：

  * 决策结论
  * 当前有效状态
  * 是否存在不同意见（icon 提示）

#### 📌 B. 行动卡区

* 行动卡列表
* 显示：

  * 负责人
  * 截止时间
  * 当前状态（未开始 / 进行中 / 已完成 / 阻塞）

#### 📌 C. 关键消息锚点

* 手动 / AI 标记的重要原文
* 点击可跳回群聊原文位置

## 四、主题卡的创建方式（降低学习成本）

### 创建入口设计（3 种）

#### ① 群聊浮窗「+」

* 新增选项：**生成主题卡**

#### ② 长按消息

* 选中多条消息 →「归入主题卡」
* 可：

  * 新建主题
  * 加入已有主题

#### ③ 手动创建

* 入口：主题列表页右上角「+」

## 五、主题卡页面结构（移动端 440px 友好）

### 页面结构（纵向）

```
[ 顶部栏 ]
← 返回 | 主题标题 | ···

[ 状态标签 + 摘要 ]

[ Tabs 切换 ]
| 决策 | 行动 | 关键消息 |

[ 内容区 ]

[ 底部操作区 ]
+ 添加决策
+ 添加行动
```

📌 Tabs 能明显降低信息密度，符合移动端习惯

## 六、主题卡与三项核心任务的关系（重点对齐作业）

### ✔ 与「任务一：决策卡」

* 决策卡 **必须归属某个主题**
* 决策详情页显示：

  > 所属主题：版本 1.2 上线（可点击）

### ✔ 与「任务二：只看我相关微摘要」

摘要支持：

* 按 **主题维度** 聚合
* 示例：

  * 「你参与的主题（3）」
  * 「本周更新主题（2）」

👉 这是**信息架构的加分点**

### ✔ 与「任务三：行动抽取与同步」

* 行动卡默认归入**当前主题**
* 外部同步时显示主题名：

  > 📅 日历事件：版本 1.2 上线 / 更新埋点

---

## 七、主题卡列表页（全局视角）

### 列表展示字段

* 主题标题
* 最近更新时间
* 决策数 / 行动数
* 当前状态

### 筛选方式

* 只看我参与
* 按状态
* 按时间

## 八、为什么这个设计对评估者“很友好”（总结给你）

你们的主题卡设计体现了：

1. **从聊天流 → 协作结构的抽象能力**
2. **信息架构清晰，有上位概念**
3. **AI 使用克制（辅助而非替代）**
4. **移动端可落地**
5. **和三大任务不是并列功能，而是有“系统性”**
