# 群聊新建卡片关联计划

## 一、 问题现状
目前在群聊界面通过右下角「+」号新建卡片时，各卡片处于孤立状态：
1.  **新建决策卡/行动卡**：无法直接归类到某个“主题”。
2.  **新建主题卡**：无法自动关联已有的决策或行动（虽然可以选择消息）。

这导致用户创建完卡片后，还需要去详情页二次编辑才能建立关联，操作割裂。

## 二、 优化目标
在创建流程中（Entry Phase）即完成关联，形成 **"主题 - 决策 - 行动"** 的上下文闭环。

## 三、 功能设计方案

### 1. 新建决策卡/行动卡 (关联上级主题)

**场景**：用户在群里根据几条消息生成一个“决策卡”。
**新增功能**：在创建页面的表单中，增加 **"关联主题" (Belongs to Theme)** 选项。

*   **UI 设计**：
    *   在“标题”下方增加一行 "所属主题"。
    *   **默认状态**：未关联 (或 "无")。
    *   **交互**：点击后弹出一层 "选择主题" (Theme Picker)，列出当前活跃的主题 (Active Themes)。
    *   **智能预测** (可选)：如果所选消息的时间段与某个活跃主题重合，自动预填该主题。

**数据流转**：
*   `CreateDecisionCard` / `CreateActionCard` -> 提交时携带 `themeId`。

### 2. 新建主题卡 (关联下级卡片)

**场景**：用户归拢一堆消息建立“主题卡”。
**新增功能**：自动识别并关联已基于这些消息创建的决策/行动卡。

*   **逻辑设计**：
    *   当用户再创建主题卡勾选消息 (Message Selection) 时。
    *   系统检查这些 Message ID 是否已经被某些 Decision ID 或 Action ID 引用。
    *   如果有，在创建成功后，自动将这些 Decision/Action 的 `themeId` 更新为新创建的主题 ID。

### 3. "创建后" 的引导反馈

*   创建决策/行动卡成功后，Toaster 提示：“已创建并关联至主题《版本1.2上线讨论》”。
*   (可选) 提供“去查看主题”的按钮。

---

## 四、 开发实施步骤 (Phase 1: 核心关联)

本阶段优先实现 **"新建决策/行动时选择主题"**，这是最高频场景。

1.  **修改 `CreateDecisionCard.tsx` 和 `CreateActionCard.tsx`**：
    *   引入 `ThemeContext` 或使用 Mock 的主题列表数据的。
    *   增加 UI 组件：`ThemeSelector` (简单的下拉或点击进入选择页)。
    *   更新 `formData` 状态，增加 `themeId`。
2.  **更新 Mock 数据源**：
    *   确保有几个预设的 Active 主题可供选择（如 "版本1.2上线讨论", "年会筹备"）。

## 五、 预期效果
用户在聊天中提取任务时，可以直接将其扔进"版本1.2"的篮子里，无需后续整理。
