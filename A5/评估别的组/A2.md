**1.2主题描述**

本项目旨在深入探究计算机专业学生在编程学习中使用AI编程助手（如ChatGPT、GitHub
Copilot等）的行为模式、内在动机及面临的深层挑战，并以此为基础，识别出当前工具和教学体系中未满足的核心需求，最终为设计更具教育价值、更负责任的下一代AI辅助学习方案提供洞见。

**2. 用户需求发现及用户画像**

**2.1 头脑风暴用户需求列表**

基于对三位受访者（P1: 常规学习者；P2: 高度依赖者；P3:
助教/领域专家）的访谈分析，我们初步归纳出以下用户需求：

需要能够快速解决编码过程中的具体错误和瓶颈，提升作业完成效率。

需要能够绕过薄弱的基础知识，快速实现复杂的项目创意和功能。

需要能够将AI作为节省重复性劳动的工具，以专注于更高层次的设计与研究。

需要能够理解和信任AI生成的代码，明确其潜在风险和质量。

需要能够明确在学术作业和项目中使用AI的合理边界，避免学术诚信风险。

需要AI工具能理解项目的全局架构和业务逻辑，而不仅仅是提供孤立的代码片段。

需要在借助AI提升效率的同时，确保对核心编程概念和问题解决能力的实质性掌握。

需要获得关于如何有效、负责任地使用AI工具的指导与最佳实践。

**2.2 最终选择的3个深度用户需求及对应画像**

**深度需求一：效率与能力的平衡需求**

学生需要在使用AI提升编程效率的同时，确保对核心编程概念和问题解决能力的实质性掌握。

**关联访谈/调查**：P1担心"能力退化"，P2的策略存在基础不牢风险，P3则从教育者角度明确指出学生可能绕过关键思考过程。研究显示，AI主要承担了创造（39.8%）和分析（30.2%）等高阶认知功能，引发了对学生自身认知能力发展的担忧。

**用户画像**：

**用户**：基于P1原型，大二计算机专业学生，学习态度认真但易焦虑。

**场景**：在完成数据结构课程大作业时，使用AI快速修复了一个复杂报错，作业得了高分。但一周后面对类似的面试题，他发现自己无法独立解决，产生了强烈的焦虑和自我怀疑。

**目标**：希望有一种方法或工具，既能利用AI节省调试时间，又能确保自己真正内化了关键的算法思想和调试技能。

**深度需求二：学术诚信的边界明确需求**

学生需要清晰、权威的指南，以界定在课程作业和项目中合理与不合理使用AI的边界。

**关联访谈/调查**：P2对学术诚信界限的模糊认知（"效率至上"）和P3作为助教的深切担忧形成鲜明对比。研究发现，近一半（约47%）的学生与AI的对话属于参与度较低的"直接对话"，仅是单纯寻求答案或内容，其中部分行为可能存在作弊嫌疑。

**用户画像**：

**用户**：基于P2原型，大三学生，善于探索和使用新技术。

**场景**：他使用AI完成了80%的Web开发课程项目，但课程大纲对AI使用的规定语焉不详。在项目评审时，助教（基于P3原型）质疑其工作量与代码原创性，双方因缺乏明确标准而产生争执。

**目标**：需要学校或教师提供清晰、具体、可操作的AI使用指南，以及能真实反映学习成果的评估方式。

**深度需求三：深度上下文协作需求**

学生需要AI编程助手能够理解项目整体架构和业务逻辑，提供更具整体性和一致性的建议，而不仅仅是获取孤立的代码片段。

**关联访谈/调查**：P2和P3都指出，当前工具对项目整体架构、业务逻辑的理解有限，学生需花费大量时间向AI"解释"项目背景。

**用户画像**：

**用户**：基于P3原型，研一助教，兼具资深开发者和教学者视角。

**场景**：在指导本科生毕业设计时，发现学生用AI生成的代码虽然单个模块能运行，但模块间接口设计混乱，缺乏整体架构观。

**目标**：需要AI编程助手能成为一个真正的"智能化编程伙伴"，深度理解代码库上下文，提供具有架构层面洞见的建议。

**4. 解决方案构思与选择**

**4.1 基于深度需求的解决方案脑暴**

**深度需求一（效率与能力平衡）的解决方案**

1.  **"思考伙伴"模式AI（AI辅助）**：AI不直接给出完整答案，而是通过苏格拉底式提醒引导学生自己找出错误和解决方案，并记录思考路径。

2.  **自适应练习生成器（AI自动化）**：在AI帮助学生解决一个难题后，自动生成数个考查相同核心概念但形式不同的练习题，强制学生独立完成，以巩固学习效果。

3.  **"AI使用日志"与学习档案（非AI/教育方案）**：要求学生在使用AI辅助完成的作业中，提交一份简短说明，记录遇到的问题、AI提供的帮助以及自己的总结。教师据此评估学习过程。

4.  **基于脑机接口的认知投入度监测（远景/风险大）**：AI在提供帮助时，实时监测学生的脑波活动以判断其是否处于积极思考状态，并根据投入度动态调整提示策略。

**深度需求二（学术诚信边界）的解决方案**

1.  **"AI使用刻度盘"课程政策模板（政策方案）**：为教师提供一个可定制的政策模板，明确不同作业允许的AI使用级别（如：完全禁止、仅限调试、允许协作、鼓励创新使用），并配套相应的评估标准。

2.  **AI贡献度透明度工具（AI辅助）**：学生在提交代码时，工具自动生成一个"AI协作报告"，概要说明AI在哪些部分提供了帮助，作为提交物的一部分。

3.  **集成式"考试模式"的编程环境（技术方案）**：在课程的关键考核中，使用特殊的IDE模式，限制对外部AI工具的访问，但内置一个功能受限的、仅能提供官方课程文档查询和基础语法提示的AI助手。

4.  **基于区块链的代码原创性溯源系统（远景/风险大）**：记录代码编写过程中的关键思维节点和修改历史，形成可验证的、防篡改的学习过程证明，用于评估学生的真实贡献。

**深度需求三（深度上下文协作）的解决方案**

1.  **"项目架构师"AI助手（AI自动化）**：AI能自动扫描和理解整个代码库的架构，在学生添加新功能时，不仅能生成代码，还能建议符合当前架构模式的最佳实现方式，并提示可能破坏现有模块的风险。

2.  **交互式代码质量审查员（AI辅助）**：AI在生成或修改代码后，自动对其进行评审，从性能、安全性、可读性、符合设计模式等角度提供评分和改进建议，并解释原因。

3.  **深度集成IDE的"项目上下文感知"插件（平台方案）**：该插件持续在后台分析开发者的编程行为和各文件间的关联，为AI提供丰富的元数据，使AI的建议基于完整的项目上下文。

4.  **"AI结对编程"虚拟角色（远景/风险大）**：一个具象化的AI程序员虚拟形象，能持续跟踪项目进度，主动参与设计讨论，基于项目目标提出质疑和替代方案。

**4.2 解决方案投票与最佳方案选择**

**A. 投票过程记录**

**便利贴投票结果**：

需求一方案中获得票数最多的：**解决方案2"自适应练习生成器"**，3票。

需求二方案中获得票数最多的：**解决方案1"AI使用刻度盘"课程政策模板**，2票。

需求三方案中获得票数最多的：**解决方案1"项目架构师AI助手"**，2票。

**四类法筛选结果**：

**最合理的**："AI使用刻度盘"课程政策模板（理由：无需高技术开发，直接解决当前最紧迫的政策真空问题，实施成本低，见效快）。

**最讨人喜欢的**："项目架构师AI助手"（理由：直击开发者痛点，想象空间大，能极大提升编程体验和项目质量）。

**最有可能令人高兴的**："自适应练习生成器"（理由：巧妙地将学习科学融入工具设计，直接缓解学生的能力焦虑，教育价值显著）。

**风险大的远景选择**："基于脑机接口的认知投入度监测"（理由：技术实现遥远，涉及伦理隐私问题，但一旦成功可能颠覆学习评估模式）。

**B. 最佳方案选择**

**最终选择的方案**：**"智学伴"AI编程学习平台（暂定名）**。该方案是 **"自适应练习生成器"（需求一）、"AI使用刻度盘"政策框架（需求二）和"交互式代码质量审查员"（需求三）**三个想法的结合与升华。

**选择理由**：经过团队讨论，我们认为单一功能的解决方案难以应对复杂的教育场景。我们最终选择这个**集成平台方案**作为最佳方案。因为它最具**系统性和创新性**，能够同时应对三个深层需求：

**针对需求一（平衡）**：平台内嵌的"自适应练习生成器"和"思考伙伴"交互模式，能有效促进知识内化。

**针对需求二（边界）**：平台集成了可配置的"AI使用刻度盘"政策提示和"AI协作报告"生成功能，为规范使用提供制度化支持。

**针对需求三（深度）**："项目上下文感知"和"代码质量审查"功能提升了AI协作的深度和价值。该方案旨在成为未来计算机教育的基础设施，在创新性、用户价值和教育意义之间取得了良好平衡。
